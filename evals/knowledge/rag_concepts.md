# 检索增强生成（RAG）概念

检索增强生成（Retrieval-Augmented Generation，RAG）是一种将信息检索与文本生成相结合的技术。它的核心思想是在 LLM 生成回答之前，先从知识库中检索相关文档片段，让模型基于这些检索到的内容进行回答。

## RAG 工作流程

1. **文档加载**：使用 DocumentLoader 从 PDF、网页、数据库等来源加载文档。
2. **文本分割**：使用 TextSplitter 将长文档切分成固定大小的块（chunks），常用 RecursiveCharacterTextSplitter。
3. **向量化存储**：使用 Embedding 模型将文本块转为向量，存入 VectorStore（如 Chroma、FAISS）。
4. **检索**：用户提问时，将问题向量化并在向量库中检索最相似的 k 个文档块。
5. **生成**：将检索到的文档块与原始问题一起组装成 Prompt，交给 LLM 生成最终答案。

## 检索策略

- **向量检索**：基于语义相似度检索，适合语义匹配场景。
- **BM25 检索**：基于关键词匹配的检索算法，适合精确匹配场景。
- **混合检索**：同时使用向量检索和 BM25 检索，通过 EnsembleRetriever 合并结果。
- **MMR（最大边际相关性）**：在相关性和多样性之间取得平衡，避免检索结果过于相似。

## 引用来源的重要性

在 RAG 系统中，引用来源至关重要。它使用户能够验证信息的准确性，并在需要时查看原始文档。好的 RAG 系统应当在回答中明确指出信息来源，例如通过 `[来源: 文件名]` 或引用编号的方式。如果知识库中没有相关信息，系统应当诚实说明，而不是编造答案。
